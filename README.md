# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 这一项，或调用 `resetModule(模块)`。

## 查询与导出（闸门启闭）

- 收窄与排先条件（筛选、排序、页码、每页条数）只认 URL query 这一份：点条件、往后翻、
  从详情页返回、另存清单读的都是同一条，详情页返回后停在原来的页码。
- 另存清单与列表同一条收窄与排先条件（全量命中行，不分页），另存出来的条数与页脚总数一致；
  台账有任何改动，列表与下一次导出同时生效（同一数据源）。
- 检索框做全字段搜索，命中结果点击直接定位到该扇闸门的详情页。

## 登记与历史回填

- 登记按业务键（闸门编号）去重：同编号重复登记会被拒绝，不会出现两条；读取侧也按 id 去重兜底。
- 历史记录回填（`backfillEntries`）的覆盖/追加裁决：**按业务键归并，业务日期（操作时间）新的
  覆盖旧的，新编号追加**——历史回填不会冲掉更新的台账；回填后全量按业务日期从新到旧排。
- 早期没有闸门类型的归类规则（裁决）：孔口尺寸与存量某扇已登记类型的闸门一致则沿用该类型
  （同尺寸同型）；对不上的统一归「未分类」，等业务确认后补录。
- 存量台账缺失的取值统一标注「待补录」，列表与导出同步显示。

## 取值与统计

- 实测值优先：当前开度有实测值时以实测为准（>0 记开启、=0 记关闭），与状态字段冲突时统一
  取实测；实测缺失（待补录）才退回状态字段判断。`measuredNumber` 是这套规则的统一入口。
- 统计卡与状态分布从全量台账计算（`computeSummary`），运营概览与模块页读到的台数相同。

## 岗位权限

- 每个模块有归属岗位（`modules.ts` 的 `OWNER_ROLES`），只有归属岗位能登记、回填、流转；
  归属之外的岗位越权改动会被数据层拒绝，页面上对应按钮同步禁用，其余人只能查看不能改。
- 头部可切换当前岗位，用于演示不同岗位的权限边界。
